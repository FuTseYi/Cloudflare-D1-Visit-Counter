# v2.0.0 — Self-Hosted Dashboard & Analytics

**Stable release · October 18, 2026**

A major usability and management update for **Cloudflare D1 Visit Counter**. Version 2.0 brings an improved self-hosted experience, a bilingual interface, editable counter URLs, and a dedicated analytics dashboard—while keeping existing counters and D1 data compatible.

## ✨ Highlights

### Redesigned, bilingual interface
- A dedicated **public showcase** (`/`) introduces the project and provides a browser-only, static badge-style demo and self-deployment guidance.
- A dedicated **owner dashboard** (`/admin`) replaces the former management form on the homepage.
- **English / 简体中文** switching across the showcase, management console, and analytics pages (`?lang=en` / `?lang=zh`), with browser-language fallback.
- Responsive, more consistent layouts, navigation, code-copy areas, and mobile styling.

### Safer counter management
- Add **Edit Counter** support, including changes to the saved badge appearance and counter URL/key.
- A protected **`POST /api/rename`** endpoint migrates totals, daily history, and saved styling in an atomic D1 batch.
- Previous **counter keys** remain compatible with existing badge and statistics links through aliases; collisions are rejected.
- Management controls require the deployment owner's `AUTH_CODE`. The sidebar stays hidden until successful authentication; navigation reflects the selected/visible section, and **Lock workspace** clears the local management session.
- Add counter search, sorting, an overview of visits, and aligned embedding snippets.

### More useful public analytics
- A redesigned **`/status?path=...`** page with total visits, today's requests, seven-day volume, daily average, and a responsive SVG trend chart.
- Switch the trend view between seven days and the available retained history.
- Clarify that visit statistics count **requests**, not unique visitors.

### Reliability and documentation
- Fix the Cloudflare **Error 1101** regression in the status page and monthly statistics API.
- Expand automated coverage of D1 rename integrity, old links, permissions, bilingual pages, and workspace interactions.
- Update the English and Chinese READMEs and developer/API documentation.

## ⬆️ Upgrading from V1

1. **Back up your D1 database** before changing a live deployment.
2. Deploy the new `worker.js` to **your own** Cloudflare Worker.
3. Retain your current `AUTH_CODE`, `ALLOWED_DOMAIN`, `ALLOWED_PATHS`, and `HISTORY_DAYS` settings and the existing `HITS` D1 binding.
4. Open `/admin`, enter your Auth Code, and manage counters as before. Existing counter totals and daily history stay in the same D1 database.

**No D1 schema migration is required.** Existing counter/image/API paths remain supported.

> **Counter key vs. Worker hostname:** Legacy aliases preserve renamed **counter keys** on the *same* Worker. They do not redirect an old custom hostname to a new `workers.dev` hostname. Update the host portion of old embeds if your Worker domain changed.

## 🔐 Self-hosting notice

The public demonstration is **not** a free badge-hosting service. To create working counters, deploy the open-source code in your own Cloudflare account and set a private Auth Code. Published badge URLs continue to count visits on the owning Worker/D1 instance.
